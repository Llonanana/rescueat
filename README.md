# RescuEat 政大惜食地圖

乞丐超人的勝利｜AI 實務專案。政大周邊打烊前的剩食地圖：找剩食、跨店組一份均衡的餐、看今天還缺多少營養、用宿舍設備把剩食煮完。

技術依提案：HTML／CSS／JavaScript＋Leaflet（底圖用國土測繪中心臺灣通用電子地圖，可切換 OpenStreetMap），資料串接 Google 試算表＋Apps Script，網站放在 GitHub Pages。

- 學生網站：https://llonanana.github.io/rescueat/
- 店家後台：https://llonanana.github.io/rescueat/shop.html

## 在 VS Code 開起來

```bash
git clone https://github.com/<你的帳號>/rescueat.git
cd rescueat
code .
```

執行 `python scripts/serve.py`，再打開 http://127.0.0.1:5500/ 。這個本機伺服器每次都回傳最新檔案，改完程式重新整理就會生效。也可以用 VS Code 的 **Live Server** 擴充功能，或直接雙擊 `index.html`，只是地圖底圖需要網路。

## 功能

| 分頁 | 做什麼 | 資料來源 |
| --- | --- | --- |
| 剩食地圖 | 地圖標出合作店家；依類別、可否微波篩選，依餐盒優先、價格、省最多、蛋白質排序；每天 19:00 起才顯示惜食價、開放預訂（之前顯示原價）；預訂後產生 4 位數取餐碼，地圖畫出取餐路線，熱量自動記進「我的營養」，可在「我的預訂」取消。店名旁 ☆ 收藏店家，收藏的店今晚有惜食時，摘要最上面和打開網站時會提醒，清單也排在最前面；店家在後台寫的公告、介紹、點數優惠顯示在店名下方。網址帶 `?shop=店家id`（店門口 QR code）會直接打開那家店 | `data/shops.js`、`data/listings.js` |
| 組一餐 | 預算內挑主食＋蛋白質＋蔬菜各一樣，依總價與步行距離排出 3 組，附 Google 地圖取餐路線；預訂後自動跳到剩食地圖並記入營養 | 同上 |
| 我的營養 | 依身高體重年齡與每週運動次數算每日熱量，DRIs 第八版查各營養素建議量；搜尋食藥署資料庫或點選 13 道常用餐點記錄今天吃的東西，顯示缺口與下一餐推薦。下一餐的熱量額度依時段：17 點後用剩餘熱量的 90%（惜食通常是當天最後一餐）、14 點後 60%、之前 45%；分數 = 補蛋白質缺口的比例（蛋白質已夠時改看熱量多接近額度）− 超過額度的懲罰 + 省下比例 × 0.3 − 估算營養 0.05，推薦理由會寫出省多少錢、是否為估算值 | `data/foods.js`、`data/dris.js`、`data/meals.js` |
| 剩食料理 | 依設備（微波爐、電鍋、快煮鍋、免開火）與手邊食材找 15 分鐘內的料理。找不到想煮的，按「幫我想一道」由 AI（Gemini）依設備、手邊食材與今天訂的惜食產生一人份食譜（今天訂的惜食可點叉叉拿掉）；每人每天 5 次、全站 200 次；做完可分享到惜食圈，貼文附上整道做法。AI 只負責想料理：每樣食材的公克數由 AI 給，熱量與蛋白質由網站對照食藥署資料重新加總（今天訂的惜食用店家的數字），對到 7 成以上食材重量才採用，否則顯示 AI 的估計並標「AI 估」；卡片上可展開看每樣食材怎麼算 | `data/recipes.js`；AI 食譜經 Apps Script 呼叫 Gemini |
| 惜食圈 | 不佔分頁：右下角的浮動按鈕打開，從右側滑出（手機佔滿畫面）。分享剩食料理（可附照片、連到食譜）、惜食開箱（只能評自己預訂過的品項）、省錢撇步；按讚。接上 Apps Script 後所有人看得到同一份動態，沒接時只存在這台瀏覽器 | Google 試算表 posts 工作表（未接時用 localStorage） |
| 資料來源 | 資料集清理結果與來源 | `data/stats.js` |
| 我的帳號 | 註冊、登入；會員的飲食紀錄保留歷史並可切換日期回看、最近 7 天熱量趨勢、預訂紀錄、收藏餐點與食譜、惜食點數與等級、點數兌換合作店家優惠（產生 P 開頭的兌換碼，到店出示；等級看累積點數，兌換不會降級）、8 個徽章、個人減量成果（救下幾份、省多少錢、減少多少碳排）。接上後端時帳號存在試算表 `users` 工作表，換裝置登入紀錄還在（密碼加鹽重複雜湊，不存明碼）；沒接後端時只存在這台瀏覽器 | `users` 工作表＋瀏覽器 localStorage |

## 重新產生資料

```bash
pip install pandas

```

## 手機 App（PWA）

網站本身就是手機 App：用手機打開網址後「加到主畫面」，就會有自己的圖示、全螢幕開啟，沒網路也能打開（`manifest.webmanifest`、`sw.js`）。

1. 把網站放上 GitHub Pages：repo 的 Settings → Pages → Source 選「Deploy from a branch」，Branch 選 `main`、資料夾 `/ (root)`，按 Save。私人 repo 需要 GitHub Pro（學生可用 GitHub Education 免費申請），或把 repo 改成公開
2. 一兩分鐘後用手機打開 `https://<帳號>.github.io/rescueat/`
3. Android（Chrome）：按頁面上方的「安裝成 App」，或選單裡的「安裝應用程式」；iPhone（Safari）：按「分享」→「加入主畫面」

離線快取對自己網站的檔案採「網路優先」：有網路一定拿最新版，所以更新網站後不用清快取。

## 接上 Google 試算表

1. 新增一份 Google 試算表，到「擴充功能 → Apps Script」，貼上 `apps-script/Code.gs` 並儲存
2. 上方函式選 `setup` 後按執行（第一次要授權），會建好 `listings`、`reservations`、`posts`、`users` 工作表和示範品項（已經建過的試算表，貼上新版 `Code.gs` 後再執行一次 `setup`，只會補上缺的工作表，不會動到原本的資料）
3. 再選 `setupShops` 執行一次，會替每家店產生 6 位數的店家後台密碼，在下方「執行記錄」看得到。密碼存在「專案設定 → 指令碼屬性」的 `SHOP_PASS_店家id`，要改密碼直接改那裡
4. 「部署 → 新增部署作業」，類型選「網頁應用程式」，執行身分選「我」，誰可以存取選「所有人」
5. 把網址貼到 `js/config.js` 的 `APPS_SCRIPT_URL`
6. AI 食譜：到 [Google AI Studio](https://aistudio.google.com/apikey) 申請 Gemini API 金鑰，存到「專案設定 → 指令碼屬性」，名稱 `GEMINI_KEY`（不要寫在程式裡）。上方函式選 `testGemini` 執行一次，會要求「連線到外部服務」的授權，並在執行記錄印出一道測試食譜。模型依序用 `gemini-2.5-flash-lite`、`gemini-flash-lite-latest`、`gemini-2.5-flash`、`gemini-flash-latest`，忙線時自動換下一個

改了 `Code.gs` 之後，到「部署 → 管理部署作業」→ 鉛筆圖示 →「版本」選「新版本」→ 部署，網址才不會變；如果用「新增部署作業」會產生新網址，要再貼一次到 `js/config.js`。

已經在用的試算表要補齊完整菜單時，貼上新版 `Code.gs` 後執行一次 `addMenu`：試算表沒有的品項會加到最後（份數 0），已有的品項只更新品名、原價、營養，不動店家填的份數和取餐截止。剩食地圖只列份數大於 0 的品項。

店家到網站的「店家後台」（`shop.html`，首頁上方提示列有連結）用自己的密碼登入，只看得到、改得到自家品項的份數、惜食價、取餐截止，也看得到今天的預訂與取餐碼；試算表不用分享給店家。後台還有：

- **本週成效**：近 7 天賣出幾份、惜食收入（以目前惜食價計）、少丟的食物與減碳、客人數、回頭客（近 30 天訂過 2 次以上），讓店家看得到成效。預訂時會記下會員或裝置代號（`reservations` 第 6 欄 `by`，不存 email）
- **店家介紹與點數優惠**：今晚公告（60 字）、店家介紹（150 字）、點數優惠與需要的點數（20–1000），存在 `shops` 工作表，顯示在剩食地圖的店名下方
- **點數兌換**：學生在「我的帳號」用點數兌換，後端依會員存在 `users` 的紀錄重算點數、扣掉 `redeems` 工作表裡已用掉的，夠才發兌換碼；店家後台列出今天的兌換碼
- **店門口 QR code 立牌**：網址是 `?shop=店家id`，按「列印立牌」印出 A4 立牌

你自己也可以直接改 `listings` 的黃色欄位。網站重新整理就會更新，學生預訂時會自動扣份數並記到 `reservations`。

接上後，惜食圈的貼文、照片和按讚存在 `posts` 工作表，所有人看得到同一份動態；作者只記會員代號（email 的雜湊），不存 email。照片會縮小到放得進試算表的一格（約 5 萬字以內）。會員帳號存在 `users` 工作表：email、暱稱、加鹽雜湊後的密碼，以及 `data` 欄裡這個會員的飲食紀錄、預訂、收藏、個人資料、徽章（JSON，改動後約 1.5 秒自動存回）。以前只存在瀏覽器的示範帳號，登入時密碼對的話會自動搬上去。登入憑證用指令碼屬性 `TOKEN_SECRET` 簽章（第一次用到時自動產生），會員 60 天、店家 14 天後要重新登入。

試算表不用分享給大眾，但網頁應用程式的網址是公開的，任何人都能透過它讀取品項和送出預訂，目前沒有防止惡意預訂的機制，正式上線前要再加上。店家後台已經驗證店家身分，每家店只能改自己的品項。

## 示範資料說明

- 品項與原價取自店家菜單：楽坡 BonBox 官網（2026/07/13 更新）、GET POWER 店內菜單（2026/11/21，餐盒價）、蛋白盒子官方線上點餐與雞肉本家 iCHEF 線上菜單（2026/11/09 查詢），四家共 92 樣；不在今晚惜食清單上的品項份數為 0
- 惜食價（原價 8 折，四捨五入到整數元）、剩餘份數、取餐時間為示範值
- 惜食時段：`js/config.js` 的 `DEAL_FROM`（預設 19:00）；19:00 打烊的 GET POWER 用 `DEAL_FROM_SHOP` 提早到 18:00。白天展示時，剩食地圖上方有「示範：直接看 19:30 的畫面」按鈕。`apps-script/Code.gs` 有同樣的設定，兩邊要一致
- 惜食點數：預訂 1 份 +10、發文 +5、有記錄飲食的每一天 +2；減量估算以每份 0.35 kg、每公斤食物浪費 2.5 kg CO₂e 計算
- 楽坡菜單註明加購品不單售；組一餐假設打烊前可單獨出清，正式上線前要和店家確認
- 營養：店家有標示的用官方數字（楽坡營養表 2026/02/09 版、GET POWER、蛋白盒子官網）；官方沒列的品項用估算，畫面上標註「估算值，僅供參考」並寫出算法：
  - 雞肉本家全部品項、楽坡杏鮑菇與泡菜、蛋白盒子單點：食藥署資料 × 假設份量
  - 楽坡加購肉品：同名弁當官方值減掉弁當基底 431 大卡、15 g（威力雞胸弁當 504 − 加購威力雞胸 73，與楽坡雞腿、舒浮彩蔬兩組官方值吻合）
  - 蛋白盒子新口味：同系列官方值類推，或「餐盒基底（香煎雞胸餐盒扣掉雞胸）＋主菜」用食藥署資料計算
- 食譜為示範，正式版需請具營養背景的同學審閱
